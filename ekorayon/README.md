# ЭКОРАЙОН — первая рабочая версия

Веб-приложение для районного учёта школьного сбора вторсырья. Стек: Node.js 20+, Express, EJS, PostgreSQL. Интерфейс адаптивный, оформление — тёмно-зелёная/молочная палитра с золотистыми акцентами.

## Что уже реализовано

- Публичная главная страница, каталог школ и карточка школы.
- Публичные рейтинги по фактической массе: школы, классы района, текущий месяц, текущий год, виды вторсырья.
- Поиск по школам, населённым пунктам, классам и опубликованным новостям.
- Вход для администрации и школ; хеширование паролей bcrypt; сессии в PostgreSQL.
- Создание школы и аккаунта школы администратором.
- Заявка школы на подключение через форму.
- Кабинет школы: внесение общего сбора или сбора по классу, исправление возвращённых записей, запросы на добавление/удаление класса, изменение численности с историей, технические обращения.
- Кабинет администрации: проверка/подтверждение/возврат записей, управление школами, обработка запросов классов, новости, обращения и журнал действий.
- Уведомления внутри системы.
- PDF-отчёт по школе (кириллица поддерживается встроенным файлом шрифта DejaVu Sans) и Excel-выгрузка.
- Обратная связь и защита от спама: Cloudflare Turnstile при настройке ключей; в режиме разработки — простой резервный проверочный пример.
- Поддержка статусов школы: активна, приостановлена, архив. Полное удаление школы доступно только главному администратору и требует явного подтверждения.
- Health endpoint `/health` для Railway.

## Важно: что ещё требуется завершить до полноценного районного запуска

Этот архив — запускаемая первая версия, а не утверждение, что абсолютно все согласованные модули уже завершены. Перед официальным использованием необходимо доработать и проверить:

1. Полноценную локализацию всех экранов и PDF на русский/белорусский (сейчас переключатель языка заложен, но перевод всех текстов ещё не завершён).
2. Иллюстрированную карту района с реальными школами и точками после получения достоверного списка адресов.
3. Общую и школьные фотогалереи, загрузку фото и модерацию медиа.
4. Формы отправки школами новостей и достижений на модерацию; каталог достижений.
5. Полный документооборот: нумерацию и закрытие месячных отчётов, районный сводный PDF, годовые документы, архив сформированных отчётов и согласованные официальные шаблоны.
6. Тонкую матрицу прав сотрудников администрации (сейчас есть роли admin/staff, но разграничение staff по каждому направлению ещё не завершено).
7. Восстановление пароля через администратора, принудительную смену временного пароля при первом входе и полноценную политику блокировок.
8. Средний сбор на учащегося и подробные рейтинги классов внутри каждой школы.
9. Регрессионное тестирование на реальных данных и проверку восстановления резервной копии PostgreSQL.

Не используйте текущую версию как официальный источник отчётности, пока не утверждены районным органом шаблоны, правила учёта и перечисленные пункты.

## Локальный запуск

Нужны Node.js 20+ и PostgreSQL 14+.

```bash
cp .env.example .env
```

Откройте `.env` и задайте `DATABASE_URL`, `SESSION_SECRET` (длинная случайная строка), `ADMIN_EMAIL` и уникальный `ADMIN_PASSWORD` (не используйте пароль из примера).

Затем выполните:

```bash
npm install
npm run db:init
npm run db:seed
npm start
```

Откройте `http://localhost:3000`. Вход администратора — адрес `ADMIN_EMAIL` и пароль `ADMIN_PASSWORD` из `.env`.

## Развёртывание на Railway + GitHub

1. Создайте новый репозиторий GitHub и загрузите в него всё содержимое этой папки.
2. В Railway создайте проект `Deploy from GitHub Repo` и выберите репозиторий.
3. Добавьте в проект Railway сервис PostgreSQL. Подключите переменную `DATABASE_URL` к приложению через Railway reference variable (обычно `${{Postgres.DATABASE_URL}}`; выберите фактическое имя PostgreSQL-сервиса).
4. В Variables приложения задайте:
   - `SESSION_SECRET` — длинный случайный секрет;
   - `ADMIN_EMAIL` — адрес главного администратора;
   - `ADMIN_PASSWORD` — уникальный сложный пароль;
   - `ADMIN_NAME` — отображаемое имя;
   - `NODE_ENV=production`.
5. Необязательно, но рекомендуется: `TURNSTILE_SITE_KEY` и `TURNSTILE_SECRET_KEY` из Cloudflare Turnstile. Если ключи не заданы, формы используют простой математический вопрос; для публичного запуска лучше включить Turnstile.
6. Railway использует `railway.json`: при старте выполняются создание/обновление схемы, подготовка начального администратора и запуск сервера.
7. После деплоя откройте домен Railway и проверьте `/health`.

**Резервные копии:** включите доступный на вашем тарифе Railway план резервного копирования PostgreSQL и отдельно организуйте регулярный экспорт базы в независимое хранилище. Проверьте процедуру восстановления, а не только факт создания копии.

## Безопасность

- Не загружайте `.env` в GitHub.
- Смените демонстрационные значения до первого публичного запуска.
- Передайте временный пароль школы ответственному лицу по защищённому каналу.
- Удаление школы удаляет связанные записи и отчётные данные из основной базы. Используйте его только при наличии отдельной архивной копии и законного основания; для обычной паузы используйте статус «paused».
- Включите HTTPS на Railway и ограничьте доступ к панели администрации.

## Структура

```text
src/                 сервер, база данных, инициализация
views/               EJS-страницы
views/partials/      общая шапка и подвал
public/              стили и шрифт для PDF
public/fonts/        DejaVu Sans и лицензия
 db/schema.sql       структура PostgreSQL
railway.json         конфигурация Railway
```

## Команды

- `npm start` — запуск приложения.
- `npm run dev` — запуск в режиме разработки с перезапуском Node.js.
- `npm run db:init` — инициализация схемы.
- `npm run db:seed` — создание начального администратора (не перезаписывает существующий адрес).
